Automate the labor, never the judgment

Short clips that add something real, and never go out without a person saying yes.

fair-clip turns long videos you have the rights to into captioned vertical clips with your own commentary. Every clip passes a blocking compliance gate and human approval before it reaches YouTube. Self-hosted, dry-run by default, one narrow OAuth scope.

Ten stages, two hard stops

The token is one clip. It can't pass ■ the compliance gate with any block, or ■ human approval without a person clicking Approve.

Why "value-add" is required, not optional

YouTube's reused-content policy applies even if you have permission from the creator. So every clip must carry original context, commentary or analysis on screen for at least a quarter of its length, written by you.

Value-add templates

Five animated explainers on top of the plain card. Each one still needs a sentence in your own words, and every word and number on it goes through the gate (links, sourced figures, screening). On vertical clips they sit above the source frame, so nothing original is covered.

The compliance gate

52 checks in 11 groups. Every one runs, and every reason is reported: 43 block the clip, 9 are warnings a person must acknowledge. The chart is generated from the code that enforces it.

Rights & originality

No rights record, no processing. Licenses that forbid edits or commercial use are refused. Value-add coverage, length and originality are measured.

Disclosures

The synthetic-content flag is set from the rights record (when unsure, disclose). Paid promotion goes private-only plus a Studio step, because the API can't set that flag.

Affiliate & markets

Disclosure at the start, at each recommendation and above the first link; allowlisted links only; no fake urgency. Securities promotion needs payer + amount; numbers need fresh sources; pump language blocks.

Disclosures where viewers actually see them

On screen near the start, on screen at the recommendation, and in the description above the first link, all checked before upload.

Security boundaries

Media is decoded only in a network-less, read-only, non-root container. The refresh token lives in your OS keychain or an encrypted vault. Only the approved clip and its exact metadata reach Google.

The review screen

Before/after, the full report, the exact request body. Approving binds the file and request hashes, so nothing can change after you say yes.

Get the app

fair-clip runs on your own computer. There is no hosted service and no account with us. Three ways in, all dry-run until you switch publishing on.

Desktop app (Ubuntu / WSL2)

One command installs a checksum-verified release into your home folder and adds fair-clip to your apps menu (the Windows Start menu on WSL2).

curl -fsSL https://raw.githubusercontent.com/Normansrule/fair-clip/main/scripts/install.sh | bash
fair-clip app

In Chrome or Edge, choose “Install fair-clip” to give it its own window.

Docker (always-on)

The app and a network-less media worker as two containers. The dashboard is published on 127.0.0.1 only.

git clone https://github.com/Normansrule/fair-clip.git
cd fair-clip
make compose-init && make compose-up

From source (try the demo)

Runs the whole pipeline on the bundled CC0 sample, no Google account needed.

git clone https://github.com/Normansrule/fair-clip.git
cd fair-clip
make setup && make demo && make dashboard
